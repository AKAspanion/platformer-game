# Fixes and Leaderboards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Leaderboards screen with a new global endless board, make every error player-facing, fix and deep-link the delete-account flow, start music only after loading, make every platform reachable, and download assets only when they are needed.

**Architecture:** Shared endless rules (score ceiling from the run's seed) are synced to `functions/shared/` like the daily rules, and a `submitEndlessScore` callable keeps one best run per player in `endless/{uid}`. `friendlyError` becomes the one place errors turn into copy. The level generator's validator checks every platform and repairs levels, and the campaign levels are regenerated. Audio and sprites move from up-front preloads to loading per level and on first use. One task wires the screens.

**Tech Stack:** Vanilla JS ES modules bundled by webpack 5 (`app/`), HTML5 Canvas and Web Audio, Firebase Web SDK 13, Cloud Functions v2 on Node 24 (`functions/`), Python 3 thumbnail script, tests via `pnpm test`, ESLint 10, GitHub Actions (`.github/workflows/ci.yml`, `.github/workflows/firebase-hosting-merge.yml`).

**Spec:** `docs/specs/2026-11-11-fixes-and-leaderboards.md`

## Global Constraints

- The branch is `feat/fixes-leaderboards`, cut from `feat/community-worlds` (PR #9). Once PR #9 merges, rebase onto `master` before opening this PR.
- No new npm dependency.
- Nothing in this plan changes production settings; the invoker permission is the developer's (spec §8).
- Firebase stays lazy: nothing loads `app/firebase/*` or `firebase/*` before the player's first input or the first use of a Firebase feature.
- `functions/shared/` is generated by `scripts/sync-functions-shared.js`; never edit it by hand.
- "No player ever sees an error code: no message contains "internal", a number in brackets such as "[0]", or a Firebase code such as "functions/…"."
- Player-facing copy is the spec's exactly.

## Checkpoints

None (`run.checkpoints: none`). The run stops before pushing (`git.push: ask`).

## Review Focus

1. An endless run with a forged seed, level or score: the server refuses it with "That run can't be ranked." (Task 2 case).
2. A Firebase error object with an odd shape (no code, a message like "internal", a status suffix "[0]" or "[500]"): the player sees player-facing copy (Task 1 case).
3. A generated level whose only route to a platform needs wings: it is repaired before use, so it never ships (Task 3 case).
4. Opening `?account=delete` while signed out, or as an anonymous player: sign-in comes first, and no anonymous account is deleted by accident (Task 5 case).
5. A level whose music finishes downloading after its sprites: music starts once everything is in, never before (Task 4 case).
