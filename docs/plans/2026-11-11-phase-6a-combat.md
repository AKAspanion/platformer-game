# Phase 6, Track A: Combat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bosses raise a shield against rapid fire, walkers shoot at medium range, and every level has a combo meter that multiplies score with sound, screen shake and a buzz.

**Architecture:** Task 1 lays the shared ground: the x4 score ceilings in the daily and endless rules (copied to `functions/shared/` by `pnpm functions:sync`), the generator's rule for which walkers may shoot, and every new sound from `scripts/generate-audio.py`. Task 2 adds the shield to the one `Boss` class (so story, boss rush, Starfall Peaks and community bosses all get it) and the medium-range shot to walkers, drawn in code like the boss projectiles. Task 3 adds a pure combo module, feeds it from the world's kill and coin paths, and draws the HUD, the shake and the Settings switch.

**Tech Stack:** Vanilla JS ES modules bundled by webpack 5 (`app/`), HTML5 Canvas, localStorage, Firebase Cloud Functions reading `functions/shared/` copies of the rules, Python 3 sound generation (`pnpm audio`, `scripts/generate-audio.py`), tests via `pnpm test` (esbuild + `node --test`), ESLint (`pnpm lint`), GitHub Actions CI (`.github/workflows/ci.yml`, which runs `node scripts/sync-functions-shared.js --check`).

**Spec:** `docs/specs/2026-11-11-phase-6-combat-mobile-rewards.md` (§1 Track A, and `combo_best` from §5)

## Global Constraints

- The branch is `feat/combat`, cut from `master`.
- No new npm or Python dependency.
- The game runs at 30 ticks a second: 0.2 s = 6 ticks, 0.5 s = 15, 2 s = 60, 3 s = 90, 4 s = 120.
- Every file under `functions/shared/` is generated: change its source under `app/`, then run `pnpm functions:sync`; never edit the copy by hand.
- Generator changes must not consume extra random numbers: story levels and the daily levels for a given seed must come out tile for tile the same as before.
- Phase 5: "The ghost never collides, collects, hurts or changes anything; it is only drawn." Spec §1.3: "Ghost runs are unchanged: they replay movement, not score."
- Analytics events never carry a name, an email or a user ID.

## Checkpoints

None (`run.checkpoints: none`). The run goes through all three tasks and stops before pushing (`git.push: ask`).

## Review Focus

1. A combo that runs across a portal: finishing a level must end it, so the next level starts at 0 and x1 (Task 3 case).
2. A real perfect daily run at x4 for every kill and coin: the server must accept it, and refuse one point more (Task 1 case).
3. A shooting walker right after the player arrives through a portal: generated walkers near the arrival spots never shoot (Task 1 case); story walkers follow the same rule at run time (Task 2 case).
4. The killing blow landing as the third rapid hit: the boss dies, with no shield rising on a dead boss (Task 2 case).
5. Screen shake with the switch off, and during hit-stop: nothing moves the camera (Task 3 case).

## Produces for later tracks

Track C (achievements and quests) reads these; their names are fixed here.

- `world.combo.best`: the highest combo reached in the current level, reset when a level loads (Task 3).
- `world.combo.count` and `world.combo.multiplier` (Task 3).
- World events in `world.events` (drained each tick by the shell in `app/index.js`, next to `vibrate`): `"combo-up"` when the multiplier goes up (Task 3); `"burn"` when a fireball burns any enemy projectile (Task 2); `"shield-up"` when a boss shield rises and `"shield-bounce"` when a fireball bounces off it (Task 2).
- `boss.bounces`: how many fireballs have bounced off this boss in this fight (Task 2), for "Beat a boss without a fireball bouncing off its shield".

```js
// app/game/combo.js
export const COMBO_WINDOW = 60; // ticks (2 s)
export const TIERS = [[20, 4], [10, 3], [5, 2]]; // [combo reached, multiplier], highest first
export function multiplierFor(count: number): 1 | 2 | 3 | 4;
export default class Combo {
  count: number;       // 0 when no combo is running
  best: number;        // highest count this level
  multiplier: 1 | 2 | 3 | 4;
  left: number;        // ticks until the combo ends (drives the HUD bar)
  /** A kill or coin: returns { count, multiplier, tierUp } after adding the step. */
  step(): { count: number, multiplier: number, tierUp: boolean };
  tick(): void;        // counts down; at 0 the combo ends
  end(): void;         // a lost heart
  resetLevel(): void;  // a new level: count, best and multiplier back to 0, 0, 1
}

// app/game/effects.js
class Effects {
  shake(px: number, ticks: number): void;
  shakeOffset(): { x: number, y: number }; // {0,0} when no shake is running
}

// app/util/settings.js — DEFAULTS gains
shake: true;

// world: `world.combo` is a Combo; events gain "combo-up"
```

Behaviour the contracts carry:

- Each kill (an enemy, or a boss defeated) and each coin calls `step()` first; its points are then multiplied by the new multiplier, the extra going into `world.bonus` (so `world.score`'s formula stays as it is). Boss hits that don't kill, and heart bonuses, don't step and aren't multiplied.
- A lost heart (`hurtPlayer` with a heart lost, `fallInPit`) calls `end()`; a shield block doesn't. A new level calls `resetLevel()`. Hit-stop freezes the combo timer with the rest of the world.
- `tierUp` plays `combo-chime`, emits `"combo-up"` (the shell buzzes with a new `vibrate` pattern `"combo-up"`: 12, 30, 12 ms) and shakes 2 px for 6 ticks; a kill at x3 or more shakes the same way. Every step plays `combo-<min(count, 8)>`.
- The shell draws the offset from `shakeOffset()` around the world (not the HUD) only when `settings.get("shake")` is on.
- HUD: beside the score, "12 · x3" with a bar under it that drains with `left`, shown from a combo of 2.
- When a level ends (through its exit, by a death, or by quitting to the menu) with `combo.best` of 5 or more, the shell tracks `combo_best { mode, combo: best }` once.
