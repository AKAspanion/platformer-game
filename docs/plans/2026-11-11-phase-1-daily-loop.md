# Phase 1: Daily Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure play with analytics, make the daily challenge free, and give it a global leaderboard, streaks and a share card, so players have a reason to come back every day.

**Architecture:** A shared, pure `app/daily/rules.js` (day keys, the score ceiling, generated names) is copied into `functions/shared/` like the world spec already is, so the client and the `submitDailyScore` callable judge runs the same way. Scores live in Firestore at `daily/{seed}/scores/{uid}`, written only by the function and readable by anyone. Players get a silent anonymous Firebase account the first time they finish a daily run. Analytics is a small queueing wrapper that lazy-loads `firebase/analytics` after the first input.

**Tech Stack:** Vanilla JS ES modules bundled by webpack 5 (`app/`), HTML5 Canvas, Firebase Web SDK 13 (Auth, Firestore, Functions, Analytics), Cloud Functions v2 on Node 24 with firebase-admin 14 (`functions/`), tests via `pnpm test` (esbuild bundles `tests/*.test.js`, run with `node --test`), ESLint 10, GitHub Actions (`.github/workflows/ci.yml`).

**Spec:** `docs/specs/2026-11-11-engagement-roadmap.md` §2 (phase 1). Phases 2–5 get their own plans.

## Global Constraints

- Base branch is `master`; this repository has no `main`. Branch: `feat/daily-loop`.

## Review Focus

1. An anonymous player opening the world creator must get the sign-in dialog, not the creator (Task 3 case).
2. A player at UTC+13 or UTC−11 submitting their local date's seed must be accepted (Task 1 case).
3. Streaks across a month or year boundary (20261130 → 20261201, 20261231 → 20270101) must count as consecutive (Task 4 case).
4. Finishing the daily while offline must keep the score and send it on the next home screen visit, once (Task 5 case).
5. An ad blocker that makes the analytics script fail to load must leave the game working with no thrown errors, and the queue capped at 50 (Task 2 case).
