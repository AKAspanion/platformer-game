# Phase 3: Community Worlds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make community worlds free to play, count plays, finishes and likes on the server, rank them by Trending, feature a world of the week, share worlds by link with a preview image, let premium players remix, and show creators how their worlds are doing.

**Architecture:** A shared, pure `app/worlds/community.js` (day keys, the trending score, the featured pick, number formatting, the creator note) is synced to `functions/shared/` like the world spec. World stats live apart from the world records, in `worldStats/{id}` with per-day buckets, so `sanitizeWorld` stays as it is for worlds. New Cloud Functions count plays and likes, keep thumbnails, pick the featured world every Monday, and serve `/w/<id>` with link-preview tags. A client module wraps those calls and reads, and one task wires it all into the Community and My worlds screens.

**Tech Stack:** Vanilla JS ES modules bundled by webpack 5 (`app/`), HTML5 Canvas, Firebase Web SDK 13 (Auth, Firestore, Functions), Firebase Hosting rewrites, Cloud Functions v2 on Node 24 with firebase-functions 7 (`onCall`, `onRequest`, `onSchedule`) and firebase-admin 14 (`functions/`), tests via `pnpm test`, ESLint 10, GitHub Actions CI (`.github/workflows/ci.yml`).

**Spec:** `docs/specs/2026-11-11-phase-3-community-worlds.md`

## Global Constraints

- The branch is `feat/community-worlds`, cut from `feat/progress-rewards` (PR #8). Once PR #8 merges, rebase onto `master` before opening this PR.
- No new npm dependency in the game or in `functions/`.
- Functions run in `asia-south1` (set once in `functions/index.js`); the Hosting rewrite names that region.
- Firebase stays lazy: nothing loads `app/firebase/*` or `firebase/*` before the player's first input or the first use of a Firebase feature.
- `functions/shared/` is generated by `scripts/sync-functions-shared.js`; never edit it by hand. Shared code imports with `.js` extensions and touches no browser globals.
- "Counts are kept by the server; the game never writes them."
- "Built-in worlds (the Dino Team's starter worlds and Starfall Peaks) have no counts, no like button and no share link."
- Player-facing copy is the spec's exactly.

## Checkpoints

None (`run.checkpoints: none`). The run goes through all four tasks and stops before pushing (`git.push: ask`).

## Review Focus

1. A player spams play or like for one world: plays count once per account per day, likes once per account, and the hourly caps hold (Task 2 case).
2. A thumbnail that isn't a PNG, or is over 100 KB, at publish: the world still publishes, without a thumbnail (Task 2 case).
3. A `/w/<id>` link whose id has HTML or quotes in the world's name: the preview page escapes it (Task 2 case).
4. Opening a world link while offline, or for a deleted world: the game opens and shows "That world doesn't exist anymore." or the offline state, never a blank screen (Task 4 case).
5. Trending with worlds whose plays are days apart: an old burst of plays ranks below a steady recent stream (Task 1 case).

- Given a canvas whose PNG is 40 KB, when `publishThumb` runs, then it returns base64 of a 480x270 PNG; given one whose PNG would be over 102,400 bytes, then null.

- Given Trending loads 3 worlds, when shown, then they appear in the server's order with "▶ <plays> · ❤ <likes>" each; switching to New shows the newest first.

- Given a community world started, when it starts, then `community.recordPlay(id, "play")` runs once; when its boss arena is beaten, `recordPlay(id, "finish")` runs once.

- Given Share pressed in a browser without a share sheet, when it runs, then `https://dino.spanion.in/w/<id>` is copied, the toast says "Link copied", and `world_share {method: "copy"}` is tracked.

- Given the game opened at `/?world=<id>` (as `/w/<id>` redirects) for an existing world, when it loads, then Community opens with that world's card at the top, ready to play, and `world_link_open {found: true}` is tracked; for a missing id, the toast "That world doesn't exist anymore." and `{found: false}`.
- Given the player's 2 published worlds had 120 plays and 37 finishes this week, when the game opens for the first time this week, then the toast "🎉 Your worlds: 120 plays and 37 boss wins this week" shows once; opening again the same week shows nothing; with 0 plays, nothing.
- Given My worlds open, when the week loads, then each published world shows its `weekNote`.
- Given a world is published, when it is sent, then its thumbnail from `previewImage` goes with it through `publishThumb`.
- Given a built-in starter world's card, when shown, then it has no counts, ❤ or Share.
- Given widths 1280 and 844x390, when Community, the banner and My worlds show, then nothing overflows and every button is reachable.
