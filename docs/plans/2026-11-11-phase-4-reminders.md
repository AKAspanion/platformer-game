# Phase 4: Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:feature-build-team by default, or ga:feature-build. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opt-in daily reminders at 18:00 in the player's time zone, at most one a day ("Today's challenge is up" or "Your <N>-day streak ends tonight"), by web push on the web and in the Android app, and through the iPhone app's existing push bridge.

**Architecture:** A shared, pure `app/reminders/rules.js` (local day and hour in an IANA time zone, which reminder a player gets, the copy, the limits) is synced to `functions/shared/` like the daily rules. A callable keeps each account's devices in `pushSubs/{uid}`; an hourly scheduled function sends the day's reminder through Firebase Cloud Messaging, reading the streak from the account's cloud save. In the game, a push module picks the iPhone bridge or web push, the service worker shows and opens the notifications, and the Settings switch and a one-time prompt turn it on.

**Tech Stack:** Vanilla JS ES modules bundled by webpack 5 (`app/`), a raw service worker (`app/sw.js`, copied by CopyPlugin), Firebase Web SDK 13 (Auth, Firestore, Functions, Messaging), Cloud Functions v2 on Node 24 with firebase-functions 7 (`onCall`, `onSchedule`) and firebase-admin 14 (Messaging) (`functions/`), the iPhone app's WKWebView push bridge (`packages/ios`, unchanged), the Android TWA's notification delegation (`packages/android`, unchanged), tests via `pnpm test`, ESLint 10, GitHub Actions CI (`.github/workflows/ci.yml`).

**Spec:** `docs/specs/2026-11-11-phase-4-reminders.md`

## Global Constraints

- No new npm dependency: Messaging is `firebase/messaging` from the existing `firebase` package, and `getMessaging` from the existing `firebase-admin`.

- "Reminders are opt-in. Nobody gets one without turning them on."
- Player-facing copy is the spec's exactly.

## Checkpoints

None (`run.checkpoints: none`). The run goes through all four tasks and stops before pushing (`git.push: ask`).

## Review Focus

1. A player in a time zone that just changed for daylight saving (for example "America/New_York" on 2026-11-01): the reminder still goes out at 18:00 local, once (Task 1 case).
2. A streak whose last day was the day before yesterday with a freeze left: it still counts as alive, so the streak message is sent (Task 1 case).
3. The hourly job running twice in the same hour, or a retry: a player never gets two reminders the same day (Task 2 case).
4. A device token from another account, or a garbage time zone, sent to the callable: refused, nothing stored (Task 2 case).
5. Turning reminders on while offline: the switch goes back to off with "Couldn't turn on reminders. Try again later." and nothing is half-saved (Task 4 case).

export async function handleSetReminders(request, deps: { subs, limiter, now? }): Promise<{ on: boolean, devices: number }>;
/** One pass: for each subscription that isDue, read the streak, send at most one message to its devices, drop unregistered tokens, stamp lastSentDay. */
export async function handleSendReminders(deps: {
  subs: { all(): AsyncIterable<{ uid, devices, timeZone, lastSentDay }>, update(uid, patch), claimDay(uid, day): Promise<boolean> },

  messaging: { send(tokens: string[], message: { title, body, link }): Promise<{ invalidTokens: string[] }> },
  now?: () => number,
}): Promise<{ sent: number, skipped: number, pruned: number }>;
